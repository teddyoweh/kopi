# KP-38 — Stream documents into the panel while Kopi writes them

**Why:** in the first real run of the KP-37 artifacts panel, the "Kopi is writing this" state
never showed. The SDK hands over a finished tool call (`AssistantMessage` → `tool_call`) only
once the model has written the whole document, and the Write itself takes milliseconds. So a
document appeared in one jump, 20–40 s after the model started on it.

**Probe (real SDK, not from memory):**
- With `include_partial_messages`, a Write arrives as `content_block_start`
  `{type: tool_use, name: "Write"}`, then about 50 `input_json_delta` fragments of
  `{"file_path": "/tmp/…/probe.md", "content": "# Probe\n\n1. **Apple** –…`, then
  `content_block_stop`.
- The block index restarts at 0 in each message.

**Built**
- **`ChatEventType.WRITING`** (additive): `file` is the draft's name and `text` is the next
  piece of its content.
- **`kopi/agent/streaming.py`, `PartialWrite`:**
  - takes the fragments and returns the content decoded so far, never half an escape
    (`\n`, `\\`, `\uXXXX`, or a surrogate pair split across fragments);
  - picks `file_path` out once its string is complete, in either key order;
  - stops at the content string's closing quote.
- **The runner's `Translator`:**
  - keeps one `PartialWrite` per top-level Write block;
  - emits `writing` events of at least 60 characters, flushing the rest on
    `content_block_stop`;
  - only for paths inside `drafts/`; never for Edit, other tools or subagents
    (`parent_tool_use_id`);
  - buffers content that arrives before `file_path` until the name is known.
- **Bid page:**
  - a `writing` event appends to the live copy (the first piece of a new write replaces
    the old copy), shows the spinner on the tab, and opens the tab unless the person
    picked another;
  - the Write's `tool_call` then swaps in the exact content;
  - the document pane follows the newest line while Kopi writes, unless the reader has
    scrolled up.
- **Mock:** `write()` streams each draft in 48-character pieces before the Write call, so
  demo mode types its documents too.

**Checked**
- `tests/test_agent_writing.py`, 17 tests:
  - every fragment size (1 to 10,000) gives back the exact document, with both ASCII-escaped
    and raw non-ASCII JSON;
  - content that comes before `file_path` is still sent;
  - events are batched;
  - nothing streams for Edit, other tools, paths outside drafts, or subagents;
  - text deltas still stream;
  - the decoder's edge cases.
- The suite is 343 passed; lint and build are clean.
- In mock mode at 1440 and 390, the Plan tab spins and the plan fills in and follows as it
  is written.

**Where the agent went wrong**
- KP-37 treated the Write `tool_call` as "Kopi is writing". A real run showed the
  `tool_call` only arrives with the finished document. Probing the SDK first showed where
  the text actually is.
- A surrogate-pair assertion lost its escape on the way into the test file (it arrived as a
  literal emoji). The test now builds the escape with `chr(92)`.
