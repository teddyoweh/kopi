# KP-31 — Contract for search insights and bid sessions

**Built (the contract the next four tasks share)**
- **Models** (`kopi/models.py`, additive):
  - `InsightsRequest`, `EligibilitySummary`, `MarketBand`, `TenderInsight`;
  - `ChatRequest.bid` (default false);
  - `SessionFile.kind` (`draft` | `upload`, default `draft`);
  - `MemoryNote`, `BidStage` (qualify, clarify, draft, review, submit), `BidMemory`,
    `MemoryRequest`.
- **Routes** (`kopi/api/app.py`):
  - `POST /search/insights` (Authed, Read, at most 25 document numbers);
  - `GET` and `POST /sessions/{id}/memory`, and `POST /sessions/{id}/memory/{note_id}/forget`
    (AppOnly);
  - `POST /sessions/{id}/uploads?name=` (AppOnly; raw body; `.pdf .md .txt .csv`; plain
    names only; empty is 400, over 8 MB is 413);
  - `GET /sessions/{id}/files/{name}` now serves each file with its media type;
  - `CopilotUnavailable` is 503 on every route.
- **Store protocol** gains `memory`, `remember`, `forget` and `upload`:
  - `FixtureStore` implements them in memory, and lists uploads with `kind="upload"`;
  - `LiveStore` delegates them to `Copilot.memory`, `Copilot.remember`, `Copilot.forget`
    and `Copilot.upload`, which **KP-33 must add to `kopi/sandbox.py`**. `Copilot.files`
    and `Copilot.file` must cover uploads too.
- **`kopi/insights.py`**: a working first version over any Store through `Store.tender`
  (eligibility summary, closest sentence, item count, envelopes, method, price band). It
  runs in series, one `tender()` call per document, which embeds the notice for its market
  band. **KP-32** makes it fast (parallel, cached, or reusing the notice's stored vector)
  and adds its own tests.
- **Web** (`lib/api.ts`):
  - `KopiApi` gains `insights`, `memory`, `remember`, `forget` and `upload(sessionId, File)`,
    with the live implementations;
  - `UPLOAD_TYPES` and `UPLOAD_LIMIT` are exported;
  - `ChatRequest.bid` is optional on the client.
- **Mock** (`lib/mock.ts`, `lib/mock-memory.ts`):
  - insights mirror the backend;
  - memory persists in localStorage; upload contents last for the tab;
  - `Beat.effect` runs when a scripted beat plays, so the scripted bid kickoff (KP-35) can
    write notes and stages as it goes, through `addNote` and `setStage` from
    `lib/mock-memory.ts`;
  - `scriptTurn` now receives the request with its `session_id` filled in.
- **`lib/bids.ts`:**
  - A `Bid` is the tracked record (same key, `kopi.submissions`) plus `session_id` and
    `profile_id`, so every tender tracked before bids existed shows up as a bid not yet
    started.
  - `useBids()` returns `bids`, `bidFor`, `startBid(notice, profileId)` and
    `attachSession(doc, sessionId)`. `startBid` returns `/bid/?doc=…&start=1` when the bid
    has no session yet.
  - `useTracked().track` no longer drops a bid's session.
- `make types` regenerated `openapi.json` and `web/lib/api-types.ts`. The Makefile's deploy
  target now uses the `kryptonairc-lc` profile.
- Tests are in `tests/test_api_contract_bids.py`: insights order and skipping, the 25 cap,
  the blocker, memory add and forget, upload listing, media types, refusals and the size
  cap. The suite is 285 passed.

**For KP-33 (bid sessions)**
- Implement `Copilot.memory`, `remember` and `forget` (memory `memory/{sid}`, with notes
  from the person as `source="you"`) and `Copilot.upload` (`upload/{sid}/{name}`, bytes).
  `remember` must raise `NotFound` for an unknown session.
- Bid mode is `ChatRequest.bid` together with `doc_no`.

**For KP-34 and KP-35 (web)**
- Call `api.insights(docs, profile, q)` after the hits render, 25 at a time.
- A bid's session comes from `useBids().bidFor(doc)?.session_id`. Call `attachSession` on
  the first event that carries a `session_id`.
- Refresh memory with `api.memory(sid)` after `remember`/`set_bid_stage` tool results and
  on `done`.

**Where the agent went wrong**
- openapi-typescript v7 marks every field that has a server default as required, so the
  first build failed on every `ChatRequest` literal missing `bid`. I made `bid` optional in
  the client's `ChatRequest` type instead of touching callers. Response types keep the
  required fields, which the servers always send.
