# KP-16 — Redacted session logs, journal, cut list, public repo

**Built**
- **`scripts/export_logs.py`** (standard library only) turns Claude Code session transcripts
  into:
  - `logs/<label>.jsonl`: one redacted event per line;
  - `logs/<label>.md`: turn-numbered and readable;
  - `logs/INDEX.md`: every session with its model, turns, tool calls, output tokens and time
    span, plus what was removed and why.
- **The export keeps an allowlist.** It keeps prompts, assistant text, tool calls and tool
  results, and drops everything else: thinking, images, system reminders and prompt
  snapshots.
  - App prompts (build state, crew reports, hooks) are clipped and labelled.
  - My own messages are separated out of the build-state prompts they arrived in.
- **Crew agents are forked from the main session**, so any record already exported is
  skipped. 286 to 470 shared records per agent appear once, in `01-main`.
- **Redaction**, applied to every string:
  - API keys and tokens, and signed Kopi tokens;
  - emails, except `noreply@anthropic.com` and `example` domains;
  - SG and US phone numbers, private IPs, home and temp paths;
  - GeBIZ contact blocks;
  - the literal values in `data/secrets/*.json`;
  - a local, gitignored `data/secrets/personal-strings.txt` (`re:`, `=>` and `omit:` rules).

  A high-entropy rule is the safety net for anything else. It needs mixed case, digits,
  real entropy and no dictionary words, so tender numbers and GeBIZ form ids survive.
- **Omitted outright:**
  - mailbox searches;
  - other agents' transcripts (each has its own log);
  - Modal resource lists from other workspaces;
  - calls touching the agent's private memory or keys;
  - the shell calls of the privacy review itself, as a manifest `private_windows` entry
    with a note left in their place.
- **The leak gate.** After redaction, every output is checked for secret literals,
  personal strings, unmasked emails, key patterns and home paths. If anything survives,
  nothing is written.
- **`logs/`:** all 12 sessions, 4.3 MB. That's the main agent, crew agents 1 and 2 (KP-4,
  KP-5), five reviewer sessions and four subagents (permits research, KP-9, KP-10, KP-13).
- **`planning/03-plan.md`:** the plan as executed. It has every task with who built it,
  when it started, lines changed and the review verdict, whether each milestone's goal
  held, and a table of where the plan changed and why.
- **`planning/05-cut-list.md`:** what was cut by design, what was cut during the build, and
  what would bring each back.
- **Corrections made while cross-checking the board:**
  - `02-decisions.md` had D12 and D13 twice after a merge. It's renumbered D1–D22, and the
    references in the README and in handoffs KP-10 and KP-15 are updated.
  - The README and the journal said a reviewer read every task. Reviewers ran on
    milestone 1 only; both now say so.
  - The README's "nothing scraped is committed" now says the logs quote short notice
    excerpts, with contact details removed.
  - The test count is now 272.
- **Public repo:** https://github.com/teddyoweh/kopi, created with `gh` on the `teddyoweh`
  account, with its description and homepage set to kopi.unv.run.

**Where the agent went wrong**
- **Redacted JSON text instead of JSON values.** The first run crashed, because redacting a
  serialised tool input broke its quoting. Redaction now walks the values.
- **The leak gate checked JSONL escapes, not what a reader sees.** It flagged
  `\n@pytest.fixture` as an email. It now checks decoded strings.
- **Truncation cut a word in half, and the gate caught it as a client name.** Cuts now
  land on whitespace.
- **The first high-entropy rule was too greedy.** It masked tender numbers and GeBIZ form
  ids. The rule is tightened, with tests both ways.
- **Checking my work added new leaks to the transcript.** Every grep over the logs printed
  what it found into the main session, which is itself exported. The privacy window
  closes that loop.
- **A cut-list claim I hadn't checked.** I first wrote that live register lookups were cut.
  `LiveStore` does use `LiveRegistry`, so the row was removed before commit.
