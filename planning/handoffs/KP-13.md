# KP-13 — Copilot, Submissions and Profile UI; the tender page's AI overview and actions

**Built**
- **Copilot** (`app/copilot/page.tsx` → `components/copilot/copilot-view.tsx`, `components/copilot/turn.tsx`,
  model in `lib/copilot.ts`)
  - A chat that streams. `text` deltas are appended and rendered as markdown as they arrive.
  - Each tool call is a quiet step row:
    - the tool in plain words: "Searched open tenders for “…”", "Checked eligibility for MOE…", "Read the
      notice …", "Wrote a draft, ….md", with the running form ("Reading the notice …") and a spinner
      while it runs;
    - the one-line result under it; a result starting "Error:" reads as "Failed: …" in the unmet colour;
    - it expands to show the tool's input (long strings cut at 600 characters) and the result.
  - `tool_result` has no tool name, so each result answers the oldest call still waiting. That handles
    parallel calls.
  - A `file` event shows a draft card in the conversation ("Saving" until the turn ends, then Open and
    download).
  - **Drafts panel**: a right rail on desktop, and a "Drafts N" button with a sheet on mobile. It lists
    `GET /sessions/{id}/files`, refreshed after every turn.
    - Preview is a side sheet with rendered markdown, "Download .md" and Copy.
    - Downloads fetch the text and save a blob, because the file routes need the bearer token.
  - **Starters** for the four parts (Overview, Permits and licences, Drafting, Submissions). They are about
    the tender when one is seeded.
  - **Seeding by URL:**
    - `/copilot?doc=X&ask=…` starts a new conversation with `doc_no: X`, sends the question once, then
      drops `ask` from the URL, so a reload doesn't send it again;
    - `/copilot?doc=X` opens (or continues) that tender's conversation;
    - an "About X, title" chip shows the tender and can be removed.
  - **Stop** aborts the stream (AbortController) and marks the turn "Stopped"; leaving the page aborts too.
  - **Sessions**: `session_id` is kept from the first event and sent on every later turn. The
    conversation lives in `sessionStorage`, so opening a tender it mentions and coming back loses
    nothing.
  - **Cost**: after `done`, quietly, "US$0.18 · 3 steps".
  - **Designed states, never raw text.** Each has its own copy and actions:

    | Response | State |
    |---|---|
    | 503 | "The copilot is being connected": browse links, Try again, and "Show the reason" with `detail` |
    | 429, turns | "This conversation is full", with New conversation |
    | 429, a day | "That's today's conversations" |
    | 429, other | "Kopi needs a moment" |
    | 401 / 403 | "You've been signed out", with Sign in again |
    | 404 | "This conversation has ended" (the session expired) |
    | `error` event | "Kopi couldn't finish this answer" |
    | stream ends without `done` | "The answer was cut off"; the text so far is kept |
    | network failure | "Kopi couldn't be reached" |

  - Long user messages (the seeded requests are deliberately precise) show four lines, with "Show the
    whole request".
- **Markdown** (`components/markdown.tsx`, no dependency)
  - It builds React elements and never HTML, so raw HTML shows as text. Links survive only for http(s),
    mailto and in-app paths.
  - It covers headings, paragraphs, nested bullet, numbered and task lists, pipe tables, block quotes,
    fenced code, and inline bold, italic, strikethrough, code and links.
  - `[placeholder]`s are tinted, and GeBIZ document numbers link to their tender.
  - A single newline is a line break.
- **Tender page** (`components/tender-ai.tsx`; KP-9's placeholders and `coming-next.tsx` are gone)
  - **AI overview**, read on request ("Read it for {profile}") and kept for the tab, per notice and
    profile:
    - `model == "extractive"` (live today) is tagged "From the notice", with a line saying there is no
      model yet: no score, no recommendation, just the notice's words;
    - a model answer shows:
      - the recommendation large (BID green, MAYBE accent, NO BID red) and a fit score out of 100;
      - the summary, what they're buying and who can bid;
      - each reason with its quote and "Verified in the notice", or, tinted red, "Not found in the
        notice… don't rely on them";
      - a banner counting unverified quotes;
      - key dates in SGT, risks, and questions for the agency, with "Draft these as clarification
        questions".
  - **Prepare a response**: the three actions open the copilot seeded with the doc and a precise request
    (`tenderAsks` in `lib/copilot.ts`), plus "Ask Kopi about this tender". It is a sticky rail on
    desktop, and on mobile it sits right after the overview.
  - **Track this tender** / **Tracking**, in the header next to View on GeBIZ, with a link to Submissions.
- **Submissions** (`components/submissions-view.tsx`, `lib/submissions.ts`, `lib/stored.ts`)
  - Tracked tenders are kept in localStorage and sorted by deadline, with closed ones last.
  - Each card has:
    - a countdown ("5 days / 19 hours"), refreshed every 30 s, red under 48 hours;
    - the deadline as `dateTime` in SGT;
    - progress ("2 of 13 done").
  - The checklist comes from `POST /tenders/{doc}/checklist`. Ticks are persisted, each item shows its
    source and due date, and the drafting item has "Draft with Kopi".
  - "Drafts for this tender": `{doc_no → [{session_id, file}]}` is recorded when a `file` event arrives,
    and each draft opens in the same preview.
  - The empty state points to Search.
- **Profile** (`components/profile-view.tsx`)
  - The fields: name, UEN, summary, capabilities, past work, contract value band, GRA supply heads
    (code and grade), BCA workheads, licences held, and bizSAFE level.
  - GRA, BCA and licences each have an explicit three-way choice: **We don't know yet** (`null`),
    **None** (`[]`) or **We hold these** (the list). The line under it says what each does to checks.
  - A "Bidding as" switch sets the active profile.
  - Save, Discard, and "Reset to seed" (confirmed) are in a bar that sticks only while there are
    unsaved changes. It is saved in localStorage through the provider's `saveProfile`.
- **Mock** (`lib/mock.ts`, `lib/mock-copilot.ts`, `lib/checklist.ts`)
  - A scripted copilot turn shaped by the request: clarification questions, a compliance matrix (as a
    table), a checklist, licences, a tender read, or a search with eligibility.
    - It emits the live event shapes with realistic pauses, streamed text and a draft.
    - Tool results are worded like `kopi.agent.tools` and cut to 160 characters like the runner.
    - Drafts persist in localStorage (`kopi.mockDrafts`), so Submissions can open them after a reload.
  - The mock overview is model-style: BID, MAYBE or NO_BID, a score, and **one verified and one
    unverified quote**.
  - The mock checklist follows `backend/kopi/checklist.py`'s rules.
- **API client** (`lib/api.ts`)
  - `ChecklistItem` and `checklist()`.
  - Every error, `/chat` included, now carries the API's `detail`, which is where the 503 and 429
    reasons live.
  - The SSE parser handles CRLF, a final message with no blank line after it, and skips a malformed
    message instead of dying.

**Decisions**
- **The overview loads on request, not on page view.** The route is limited to 40 an hour and will cost
  a model call. A read is cached in sessionStorage under the doc and a hash of the whole profile, so an
  edited profile gets a new read.
- **`?ask=` sends at once.** The actions are explicit clicks asking for a specific draft, so pre-filling
  the box would add a step for nothing. `ask` leaves the URL after sending, so neither a reload nor a
  shared link spends a second turn.
- **The conversation lives in sessionStorage, not localStorage.** That matches the token's lifetime.
  Server sessions expire and cap at 20 turns, so an old conversation restored days later would only
  fail.
- **Tender links for drafts are kept in localStorage.** They can outlive the server's copy, so the
  preview says "Kopi no longer has it" on a 404 instead of erroring.
- **A draft belongs to the tender named in its file name first**, and the conversation's tender second.
  The prompt names drafts `<doc_no>-<kind>.md`, and a conversation about one tender can draft for
  another.
- **Step results are cleaned for reading, not rewritten.**
  - `<notice>` delimiters are stripped;
  - the profile JSON becomes "The profile of X";
  - "File created successfully at /workspace/drafts/…" becomes "Saved to the drafts".

  The full result is still in the expanded row.
- **A newline is a line break in markdown.** Drafts put "To:" and "Tender closes:" on consecutive lines,
  and strict CommonMark joined them into one line.
- **Recommendation colours:** BID uses `--met`, MAYBE the accent, NO BID `--unmet`. Unverified quotes use
  `--unmet-soft` and a warning line, so they never look like evidence.
- **Profile rules:**
  - "We hold these" with no rows is invalid (Save disabled, with a message) rather than silently saved
    as None;
  - bizSAFE has no "None", because the backend reads any non-level string as Unknown; `null` is the only
    honest "not certified / don't know".
- **Ticks are per tender, not per profile.** A person tracks one bid at a time; switching the profile
  rebuilds the checklist but keeps what they ticked.
- **The submit item's detail drops its first sentence.** The API writes "Closes 05 Oct 2026, 04:00 PM
  SGT." and the due line under it already says the same in the app's format.
- **No new dependency**, so there's no entry in `02-decisions.md`.

**For the next agent**
- **The copilot is live code waiting on a secret.** `/chat` is 503 until `kopi-claude`
  (`CLAUDE_CODE_OAUTH_TOKEN`) exists in Modal. Nothing in the web should need to change then.
- **Drafts reach `/sessions/{id}/files` only after the turn ends**, because the sandbox copies them out
  afterwards. The UI shows "Saving" on a file card until `done`, then refreshes the list. If KP-12 starts
  saving drafts mid-turn, the card can enable Open sooner.
- **Two things are mirrored by hand. Change both sides together.**
  - `ChatEvent` is in `lib/api.ts`, and the reducer that consumes it is in `lib/copilot.ts`.
  - `lib/checklist.ts` copies `backend/kopi/checklist.py` for the mock.
- **Storage keys:**

  | Where | Key | Holds |
  |---|---|---|
  | localStorage | `kopi.submissions` | tracked tenders |
  | localStorage | `kopi.checklistTicks` | ticks |
  | localStorage | `kopi.tenderDrafts` | drafts per tender |
  | localStorage | `kopi.mockDrafts` | mock drafts |
  | sessionStorage | `kopi.copilot` | the conversation |
  | sessionStorage | `kopi.overview.<doc>.<profile hash>` | overview reads |
  | sessionStorage | `kopi.tenderTitles` | titles for the copilot's chip |

  `useStored` (`lib/stored.ts`) is the only way to read or write them from components. It keeps every
  view of a key in step.
- **For the backend:**
  - the checklist's submit detail uses `%d %b %Y, %I:%M %p` ("05 Oct 2026, 04:00 PM"), and the web
    writes "5 Oct 2026, 4:00 pm SGT";
  - eligibility checklist ids are positional (`eligibility-1`…), so a tick can move to another item if
    eligibility changes. Ids from the requirement would be stable.
- **Not built:**
  - a list of past conversations (only the current one, per tab);
  - opening the conversation a Submissions draft came from;
  - ticks syncing across devices.
- **Scripts**, in `/tmp/kopi-shots`, outside the repo:
  - `node shoot13.mjs <out> <shots> <live|mock> [widths]` takes the screenshots;
  - `node interact13.mjs <out> <live|mock>` runs the checks.

  Both use KP-9's port mapping (localhost:3000 → 4790), and read the access code at run time.

**Where the agent went wrong**
- **I papered over a deploy gap.** At the start, live answered the new checklist route with a bare 404,
  because the deployment was older than main. I added a browser-side fallback that rebuilt the checklist
  from the same rules. Mid-task the route went live (200) and the fallback became code that could only
  hide a future regression. I removed it. I should have flagged the deploy lag instead of working around
  it.
- **Full-page screenshots put sticky bars mid-page.** The header, the composer and the profile's save
  bar landed mid-image. Scrolling to the top wasn't enough, because Chrome paints sticky-bottom elements
  where the first screen ended.
  - Fix: `shoot13` grows the viewport to the page height before capturing.
  - The profile's save bar now sticks only while there are unsaved changes, which is the better
    behaviour anyway.
- **Found only by reading screenshots:**
  - the draft preview showed its title twice (the sheet header and the draft's own heading);
  - "To:" and "Tender closes:" ran together, because single newlines were joined;
  - the extractive overview quoted the same sentence it showed as "what they're buying";
  - a clamped user message leaked half a fifth line into its padding;
  - the composer placeholder wrapped and was cut at 390;
  - the mock summary lowercased a Title Case title ("wants a supplier for design, Development…").
- **Text around names:**
  - "BrightClean Services Pte. Ltd.." was a double period, where the name ended a sentence in the seeded
    request;
  - "You hold no a BCA registration." came from a template that put a noun phrase after "no".

  Both were caught in the live screenshots, and both requests were reworded.
- **Two buttons shared the accessible name "Stop"** ("Stop" and "Stop asking about this tender"). The
  interaction test's strict locator caught it. They are now "Stop the answer" and "Remove the tender from
  this conversation".
- **A bug in my own test.** `page.unroute` was given a new function instead of the matcher it was
  registered with, so `/chat` stayed intercepted, and the real 503 check timed out on a 401. The app was
  right, and the test now keeps the matcher.
- **Not proven:** a real Claude stream through this UI. The live checks replay the runner's documented
  event format, not a real turn, because the secret doesn't exist yet.
