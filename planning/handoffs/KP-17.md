**How it was shot** (the rig is in `~/Documents/codes/kopi/data/film-rig/`, which is gitignored)
- **`record.mjs`** drives headless Chrome through playwright-core.
  - It captures every painted frame through CDP `Page.startScreencast`.
  - Typing and scrolling are human-paced, and a drawn cursor follows the mouse.
  - The access code is never typed on camera: a token is minted from `data/secrets/app.json`
    and put in sessionStorage.
  - Run it as `node record.mjs <scene…>`.
- **`reencode.py`** puts the frames on an exact 30 fps grid. Each tick is a hard-linked JPEG,
  and ffmpeg encodes the sequence with `-crf 16`.
- **`film_api.py`** is Kopi's own API on this Mac, with the same `create_app` and `LiveStore`:
  - live NeedleDB (read key) and the notice bundle copied from the `kopi-data` Volume into
    `/tmp` (GeBIZ content, never committed);
  - Claude through the local login;
  - the copilot's sandbox swapped for a temp folder running the same `kopi.agent.runner`.
- The film API and a static server for the local web build run as the `film-api` and
  `film-web` dev services.
- Claude spend for the footage was one overview (about $0.05) and three copilot turns
  (about $0.2 each).

**Where the agent went wrong**
- **Checked "done" by a button that was always there.** The first copilot take stopped
  recording mid-answer: the "Open|Download" locator matched something visible early. It now
  waits for "Stop the answer" to appear and then disappear.
- **Trusted the browser's frame clock and the concat demuxer.** Clips came out up to 50%
  longer than real time. The browser's frame timestamps and my stop time were on different
  clocks, and ffmpeg's concat demuxer drifts when fed hundreds of sub-frame durations. The
  fix is host-clock timestamps and a real 30 fps image sequence, so every clip now matches
  its frames to within a frame.
- **Filmed an empty page.** Submissions showed "Nothing tracked yet" in a fresh browser. The
  scene now tracks the tender first.
