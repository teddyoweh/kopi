# KP-21 — Say where a verified quote was found: the notice or the profile

**What was wrong**
While filming (KP-17), a real Claude overview of MOE000ETQ26000222 showed "Retrieval and
knowledge systems" as **Verified in the notice**. The phrase is in Pragnition's profile, not
in the notice. `verify()` has always checked quotes against the notice *and* the profile, on
purpose, because a reason often quotes what the company does. The UI, though, labelled every
match as the notice's. So a quote about ourselves read as if the agency had written it. For a
product whose promise is "every quote is checked", that is the wrong kind of error.

**Built**
- `Reason.found_in: "notice" | "profile" | None` (additive in `models.py`). Only code sets it,
  like `verified`, and it's excluded from the model's schema. The schema test's code-only list
  now includes it.
- `overview.found_in()`: the notice first, then the profile. A quote found in both is credited
  to the notice, because that's the evidence that matters. `verified` stays
  `found_in is not None`, so the BID → MAYBE cap is unchanged.
- The two places that build a reason without Claude say `found_in="notice"`:
  - the extractive fallback in `api/live.py`;
  - the fixture overview in `store.py`.

  Both are one-line data changes outside this task's declared files, made so that every
  path tells the truth.
- `tender-ai.tsx` labels a quote:
  - **Verified in the notice**, when it's the notice's;
  - **From your profile**, when it's the company's;
  - plain **Verified**, for an overview cached before this field existed.

  An unverified quote now says it was found in neither the notice nor the profile.
- The mock sets `found_in` like the backend. `openapi.json` and `web/lib/api-types.ts` were
  regenerated; the diff is only the new field.
- Tests cover a profile quote, a notice quote, a quote in both (credited to the notice), a
  quote found nowhere, and a model that tries to set `found_in` itself (ignored).

**For the next agent**
- Deploy: redeploy the API so the hosted fallback and overviews carry `found_in`. A redeploy
  also clears the container's overview cache. Then rebuild and republish the web.
- `make types` calls `create_app()` with no arguments, which no longer works. Generate with
  `create_app(FixtureStore(), Settings(access_codes=[]))`, as this task did.

**Where the agent went wrong**
- **The label was wrong from KP-10 and KP-13, and no check caught it.** Tests covered "is it
  verified", never "verified *where*". The UI said something the backend never claimed. It
  surfaced only because a real model overview was read closely on camera. Any label that
  names a source now needs a test that the source is the one named.
