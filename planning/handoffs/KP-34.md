# KP-34 — Bid sessions: memory, uploads, restore and the bid playbook

**Built**
- **Bid memory** (`kopi/sandbox.py`):
  - `Copilot.memory`, `remember` and `forget`, stored as BidMemory JSON at `memory/{sid}`.
  - An unknown session or note is `NotFound`. The person's notes are `source="you"`, each
    with a 12-hex random id, as `FixtureStore` does.
  - `forget` also adds the note's id to `forgotten/{sid}` (a tombstone).
- **Uploads:**
  - `Copilot.upload` keeps the bytes at `upload/{sid}/{name}` and lists the file in the
    session record with `kind="upload"`.
  - `files` lists drafts, then uploads. `file` serves either, and a blob the store has lost
    is `NotFound`.
- **Before every turn**, `_restore` writes into the sandbox whatever it is missing:
  - every draft, when the sandbox is new (a new session, or the old sandbox died);
  - any upload it does not hold yet: `record["inputs"]` is `{name: modified}` for the
    current sandbox, so a re-upload goes in again;
  - in a bid turn, `memory.json`.

  The writes go through `WRITE_FILES`, a `python -c` script. Content travels in env vars as
  base64 chunks: at most 100 KB per variable and 500 KB per exec. The script prints how many
  parts it wrote. If that count is wrong, the turn fails with `CopilotUnavailable` (503)
  rather than starting without its documents.
- **A bid turn** is `ChatRequest.bid` together with `doc_no`:
  - the runner gets `--bid`;
  - the cap is `Limits.bid_turns_per_session = 60`.
- **Memory merge** (`merge_memory`):
  - Notes are the union by id of the store's notes and the sandbox's new notes, less any
    tombstoned id. Only `source="kopi"` notes can come from the sandbox.
  - `stage` and `next_step` come from the sandbox when the agent changed them during the
    turn.
  - It runs at three points:
    - after each `remember` or `set_bid_stage` result, before that event is forwarded, so
      the browser's refresh already sees it;
    - at the end of the turn;
    - at the start of a bid turn in a sandbox that lived on. That start-of-turn merge
      recovers a turn the browser walked away from: the generator is closed, so the
      end-of-turn code never ran.
- **End of turn:**
  - It re-reads the session record before writing it, and so does the start after the
    sandbox is up. An upload made meanwhile stays listed.
  - A draft is stored only if its text changed, so `modified` is now true.
- **Agent** (`kopi/agent/**`):
  - `tools.build_bid_tools(memory_file)`:
    - `remember(note)` collapses whitespace and refuses exact repeats;
    - `set_bid_stage(stage, next_step)`.

    The installed SDK's `create_sdk_mcp_server` runs `jsonschema.validate` before a handler
    and turns handler exceptions into error results, so the enum and length limits in the
    schema are enforced. `memory.json` is replaced whole, through `.partial` and `replace()`.
  - `runner --bid`:
    - the bid prompt, built from `memory.json` and the files in `drafts/` and `inputs/`
      (with sizes);
    - the two memory tools;
    - `max_turns` 40 and $5 (`KOPI_MAX_BUDGET_USD` overrides either mode).

    Non-bid turns keep 16 turns, $2 and the old prompt: `SYSTEM` is byte-identical.
  - `ChatEvent.tool` is now set on `tool_result` too, from the tool-use id.
  - `prompts.BID`, the playbook:
    - read the tender, eligibility, profile, market, licences and every upload;
    - `remember` the key facts;
    - write the bid plan (go/no-go, gaps, a timeline back-scheduled from closing), then the
      clarification questions, compliance matrix, checklist and proposal outline;
    - `set_bid_stage` as it goes;
    - end with what it did and exactly what it needs from the person.

    The current memory sits inside `<memory>` delimiters, with the tags escaped, followed by
    the document list.
- **Tests:** `tests/test_bid_sessions.py` (26 tests). The sandbox is a temp folder, so the
  real `python -c` scripts run in it. The store pickles on every read, like Modal's Dict.
  The agent calls the real bid tools. `test_sandbox.py`'s `FakeBox` now answers the writer.
  I checked the key behaviours by mutation: without the re-read, the pre-turn merge, the
  mid-turn sync, the tombstones, the source filter, the restore or 4-aligned chunks, a test
  fails. The suite is **311 passed**.

**Decisions and why**
- **Restore covers every session. Memory covers only bid turns.** The brief did not limit
  restore to bids, and a normal session whose sandbox died now gets its drafts back. This is
  the one change a non-bid turn can see.
- **Everything is base64, not only binaries.** One writer handles any bytes. The film rig
  rewrites `/workspace` inside env values, and it cannot touch base64 content.
- **Several chunks go in one exec.**
  - An 8 MB upload is about 11 MB of base64: 112 execs at one chunk each, or 23 batched.
  - Linux refuses a single string over 128 KB (MAX_ARG_STRLEN) and caps argv plus env at
    2 MB.
  - On macOS the total is 1 MiB (`getconf ARG_MAX` = 1048576), and the local rig adds
    `os.environ` to it, hence 500 KB per exec.
- **An upload's `modified` time is its version.** Only the turn writes `inputs`, and only
  `upload()` writes an upload's meta, so neither can undo the other.
- **Tombstones.** Without them, a Kopi note the person forgot after it synced would come
  back from the sandbox's `memory.json`, mid-turn or in the next turn.
- **Only the API makes "you" notes.** The prompt tells the agent to follow "you" notes.
  Filtering the sandbox's notes to `source="kopi"` stops injected notice text from forging
  one. It also closes the direct route: the guard fix below stops the agent writing
  `memory.json`.
- **Memory and documents go in the system prompt, rebuilt each turn**, not in the user
  message. A resumed transcript never carries stale copies. The cost is a prompt-cache miss
  on a resumed turn; that cache lasts only minutes anyway.
- **Draft names stay `<doc_no>-<kind>.md`.** The bid prompt adds bid-plan, pricing-notes and
  risk-register to the kinds (cover-letter and proposal-outline were already allowed). The
  non-bid prompt keeps its list.

**For the next agent**
- **Web (KP-35):**
  - Send `bid: true` with `doc_no` on every turn of a bid. A turn without it is an ordinary
    turn: 20-turn cap, no memory.
  - Refresh memory when a `tool_result` has `tool` of `remember` or `set_bid_stage`; the
    store already has the change by then.
  - The comment in `web/lib/api.ts` that "a tool_result carries no tool name" is out of
    date. I did not touch web/.
- **Modal store risks (not verified live):**
  - Dict entries expire after 7 days without a read or write (docstring in modal 1.6.0's
    `dict.py`). A bid spans weeks, so an untouched upload can vanish: `file()` then answers
    404, and restore skips it.
  - The client does not document a Dict value cap, and an oversized put raises
    `RequestSizeError` (413). An 8 MB upload into `kopi-sessions` is untried.

  If either bites, keep drafts and uploads on a Volume under the same keys; the
  `SessionStore` protocol does not change.
- **Also untested:**
  - A new sandbox with many MB of uploads spends seconds in execs before the runner starts.
    `/chat` shows nothing until the first event, because it waits for that event to map
    errors to 503 and 429.
  - The mid-turn sync runs an exec while the runner's exec is still streaming. Modal allows
    concurrent execs in one sandbox, but this has not been tried on Modal.
  - Claude Code's Read on a PDF in `inputs/` has not been tried in the sandbox image.
- **The film rig** (`data/film-rig/film_api.py`, gitignored and not edited) needs, for bid
  sessions:
  - One folder and a unique id per box. `LocalBoxes.create()` wipes `/tmp/workspace` and
    every box has id `workspace`. So a second session wipes the first one's files, and the
    first session's next turn finds a live box and skips restore. Use, for example,
    `root = Path(tempfile.mkdtemp(prefix="kopi-box-")) / "workspace"` with
    `id = root.parent.name`, and never delete another box.
  - Keep mapping `/workspace` to the folder in both argv and env values: `WRITE_FILES` reads
    its paths from `KOPI_PARTS`.
  - `MemoryStore` forgets every session, memory and upload when the process restarts.

**Where the agent went wrong**
- **End-of-turn write.** My first design wrote the session record back from the turn's own
  copy at the end, as the old code did. With Modal's copy-on-read Dict, an upload made during
  a turn would vanish from the shelf. The tests' `MemoryStore` hides this, because every
  read returns the same object. Fix: the start (after the sandbox is up) and the end both
  re-read the record, and the new tests use a pickling store.
- **Tombstone test.** My first test only forgot one of the person's notes, which the
  `source="kopi"` filter already blocks, and a mutation run showed tombstones were untested.
  Fix: the test now forgets one of Kopi's notes after it synced.
- **Chunk-size mutation.** My first mutation set the chunk size to 100_004. That is a
  multiple of 4, so it proved nothing. I re-ran it with 99_999, and the test fails as it
  should.
- **Missing drafts.** My first `file()` called `.encode()` on a draft that might be missing:
  a 500 where the old code gave a 404. Reading Modal's Dict expiry made me look again. Fix:
  `_content` returns None, `file()` turns that into `NotFound`, and restore skips it.
- **Guard hole (found, not made).** The guard resolved a relative Write/Edit path against
  `drafts/`, while Claude Code resolves it against the cwd. So `Edit memory.json` was judged
  `drafts/memory.json` and allowed. It now resolves against the workspace.
