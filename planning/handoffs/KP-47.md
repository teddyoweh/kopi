# KP-47: Fill the company profile from its website

**Done** (Teddy, 1 Oct: "in company profile allow put website and agent search and fills
company profile. essential")
- **The profile page opens with Website.** Type the address and press **Fill with Kopi**.
  - Each step streams in as it happens: pages read, web searches, ACRA, GRA, BCA, bizSAFE,
    GeBIZ.
  - The form fills. Every field Kopi changed carries a tag saying where it came from ("From
    ACRA", "From the register", "From GeBIZ", "From the website").
  - "Where each field came from" lists the quotes and their pages. A quote Kopi didn't read
    itself is marked "not checked word for word".
  - Nothing is saved until the person presses Save. The steps fold away once it is done.
- **`kopi/profile_research.py`** works in four stages:
  1. **The website, read by Kopi itself:** the home page and up to five about, services,
     projects, clients or contact pages on the same host. The SSRF guard allows http(s) only,
     to hosts that resolve only to public addresses, re-checks every redirect, and caps a page
     at 2 MB.
  2. **A web research agent** (`WebResearcher`): Claude with only WebSearch and WebFetch,
     structured output, 16 turns at most. It gets the address, the name and UEN the person
     already has, and the pages Kopi read. It fetches what was missing, searches for the legal
     name and UEN, and finds the work done. Each search and read is streamed as a step.
  3. **The registers by UEN** (`LiveRegistry`): ACRA must agree that the UEN belongs to the
     company, or it is dropped. Then GRA, BCA and bizSAFE. A register that doesn't answer
     leaves its field as it was.
  4. **GeBIZ** (data.gov.sg): the company's awards, matched on its name without "Pte. Ltd."
     and the like. The newest five become past work, without reference codes or lead-ins,
     and the contract-value band is set from them.
- **Honest results.**
  - Every website quote is checked word for word against the pages Kopi read itself
    (`verified`).
  - A "name" that is only the web address is ignored.
  - When little is found, the result says so instead of claiming the profile was filled.

- **Tests (360):** offline, with DNS faked and pages served by `httpx.MockTransport`.
  - Addresses: private and odd addresses are refused, as is a redirect inward.
  - Pages: six at most.
  - UEN and register checks: a labelled UEN is preferred, an ACRA mismatch drops the UEN,
    and an unanswered register changes nothing.
  - Agent: a site that refuses readers is still researched on the web, a failed agent falls
    back to the site's own words, and an agent that finds nothing doesn't rename the company.
  - GeBIZ: award lines are cleaned, and matching is exact.
  - Route: steps stream, then the draft.

**Decisions:** D32.

**Where the agent went wrong**
- The first version read only the website, with a toolless Claude. On the first real sites,
  NCS refused the reader (403) and ISS's page was built by JavaScript and came back empty. I
  had tested only on synthetic pages, which can't show either case. The web agent, probed
  first (23 s, US$0.09 for NCS's UEN), fixed both.
- Regenerating the API types dropped the research schemas, because a streaming route declares
  no model. They had been written into `openapi.json` by hand, from the other Mac. The route
  now declares `ResearchEvent`, so they generate.
- Two Macs built the same card at once. I kept the one the page imported, took the other's
  better idea (tags that say where each value came from) and deleted the duplicate.
