# KP-14 — End-to-end on live data, QA, and publishing the app

**Published:** **https://kopi.unv.run** (static, public; version 1). The site itself holds no
data. Everything comes from the Kopi API, which requires the access code, so no GeBIZ
content is on the open web (D9). The code is shared with the submission and kept in
`data/secrets/app.json` (gitignored).

**How it's built for live**
- `web/.env.production` holds `NEXT_PUBLIC_KOPI_API=https://kryptonairc-lc--kopi-api.modal.run`.
  It's public by design, so it's committed, and `web/.gitignore` makes a single exception
  for it.
- **`site_publish` can't build a Node project on this Mac.** Its `npm ci` runs with
  `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, and `npm`'s `#!/usr/bin/env node` can't find
  Homebrew's node. `/usr/local/bin` isn't writable without sudo.
- **To publish:** build here and publish the static export as a plain folder.

  ```
  cd web && PATH=/opt/homebrew/bin:$PATH npm ci && npm run build
  rm -rf <session>/artifacts/apps/kopi && mkdir <session>/artifacts/apps/kopi
  cp -R out/. <session>/artifacts/apps/kopi/
  site_publish artifacts/apps/kopi        # same URL every time
  ```

**Where the agent went wrong**
- **Symlinked source for publishing.** I first tried `site_publish` on a symlink to the
  Next.js source, and its `npm ci` failed. That's the same PATH problem that made
  `site_scaffold` fail at the start of the build ("spawn npx ENOENT"), and I should have
  expected it. Switched to publishing the static export.
- **My QA selectors.** "Open opportunities" first matched a hidden sidebar footnote,
  and the overview button is labelled "Read it for Pragnition Labs", not "overview". Both
  were my test's fault, not the app's; the waits are now scoped to `main`.
